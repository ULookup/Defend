## 修复结果（2026-10-13）

用户确认修复后，下述两处问题均已解决。开始页进入时默认选中「开始守望」，五个菜单按钮都有独立青色焦点边角，导航焦点不会使用持续按压底图。档案分类与条目文字跟随实际底图切换深浅颜色，兼容鼠标悬停、按压、键盘焦点与键盘提交后恢复。

## 已确认的问题

### 1. 主菜单的键盘焦点不完善（中等）

首次进入开始页，EventSystem 当前选中对象与 First Selected 均为空。实际注入一次向下方向键，Input System 的 move 动作回调已收到输入，但选中对象仍为空。因此首次进入后，方向键无法开始菜单导航，需要先用鼠标建立选中对象。

已有焦点时，将选中对象从空切换为「开始守望」，按钮图片、文字颜色均没有变化，也没有启用的 Outline。虽可提交已选按钮，但用户无法从画面判断当前键盘焦点。

证据：`Results.json` 的 `initialKeyboardNavigation` 与 `keyboardFocusIndicator`；`Assets/Defend/Scripts/Unity/UI/DefenseInterface.cs` 的 `ShowStart`；`Assets/Defend/Scripts/Unity/UI/MainMenuButtonFeedback.cs` 的 `OnSelect` / `Refresh`；场景 EventSystem 的 First Selected 为空。

建议：首页显示时选中首个有效按钮，并增加独立的焦点描边或其他可见焦点提示。焦点提示应与鼠标按压图片分开，避免重现此前返回后按钮持续按压的问题。验证首次方向键导航、返回后的焦点恢复与默认按钮外观。

### 2. 档案按钮悬停时文字难辨（中等）

打开档案，切到防御工事，在未选中的「反应堆」条目上悬停。背景切换为深色 Pressed 图片，但文字保持 `RGBA(0.170, 0.200, 0.230, 1.000)` 深色，名称几乎融入按钮背景。分类按钮也共用同一个 Style 状态配置。

证据：`Archive-hover.png`（反应堆条目）；`Results.json` 的 `archiveHoverContrast`；`Assets/Defend/Scripts/Unity/UI/DefenseArchiveView.cs` 的 `Style` 将 highlightedSprite / pressedSprite 设置为深色图，但文字颜色只依赖条目是否选中。

建议：在悬停 / 按下时同步切换为浅色文字，离开后恢复对应选中或未选中文字颜色。验证三类分类按钮与条目按钮，避免影响持久的选中高亮。
